# 파벌 · 모임 · 저택 행사 — 서로 맞물리는 사회 시스템 설계 (BL23)

**오너 지시 (2026-09-28)**
- "1챕터가 길어져도 사람들과 재밌는 교류나 새 이벤트가 공백을 채우면 괜찮다. 이벤트에서 살인의 기회도 생긴다."
- "이벤트와 살인과 트릭이 연계되게 많이, 다양하게."
- "이벤트는 NPC가 자연스럽게 제안하고, 각자의 생각과 관계에 따라 참여·불참한다."
- "친밀도가 높은 그룹은 파벌이 된다."

이 문서는 그 시스템들이 **서로 어떻게 물리는지**를 먼저 정하고, 구현 순서와 파일을 적는다. 모든 선택은 결정론(해시·기존 스트림)이고, 세이브 왕복이 같아야 한다.

## 1. 전체 고리

```
관계(좋아함·신뢰·애착) ──► 파벌(무리·리더·경쟁 무리·외톨이)
        ▲                       │ 초대 대상 · 수락/거절 · 자리 · 감싸기
        │                       ▼
   장면의 선택 ◄── 모임과 행사 (주민 제안 · 파벌 모임 · 저택 행사)
                                │ 모임이 곧 살인의 무대가 된다
                                │ (혼잡 · 소등 · 가면 · 흩어짐 · 알리바이)
                                ▼
                  살인 설계(Initiative Moments) ──► 사건 ──► 심판
                                                         │
          파벌의 감싸기·몰표 · 가면 오인 · 구역 알리바이 ◄──┘
```

## 2. 파벌 (`Sim/Life/Factions.cs`)

**계산 시점과 방법**
- 매일 06:00과 챕터 시작에 계산한다.
- 친밀도는 두 사람 사이의 (좋아함 + 신뢰 + 애착) / 3을 양방향 평균낸 값이다. 인물 관계도의 매듭이 있으면 +0.05.
- 가장 가까운 쌍(≥ 0.22)부터 무리를 시작한다.
  - 무리 평균 친밀도가 0.18 이상인 사람이 합류한다.
  - 무리는 최대 5명이고, 한 사람은 무리 하나에만 속한다.
- 어제의 무리와 겹치는 정도로 같은 무리인지 이어서 판단한다. 그래서 합류·이탈·해체가 사건이 된다.

**무리의 구성**
- **리더:** 무리 안에서의 친밀도, 자존심, 사교성의 합이 가장 큰 사람.
- **이름:** 주민들이 부르는 말로 짓는다("시온네", "서재 사람들"). 리더 이름이나 무리가 주로 모이는 방에서 딴다.
- **경쟁 무리:** 두 무리 사이 평균 친밀도가 −0.05 미만.
- **외톨이:** 2일차 이후 어느 무리에도 없는 사람.

**효과**

| 어디에 | 효과 |
|---|---|
| 초대 | 모임 주최자는 자기 무리부터 초대한다. |
| 수락 | 같은 무리 주최 +0.35, 경쟁 무리 리더 주최 −0.3, 리더가 거절하면 무리원 −0.15 |
| 식탁 | 새 무리·이탈·경쟁이 식탁 주제가 된다(`tt_faction`). |
| 관계 흐름 | 무리 안에서는 좋아함·신뢰가 매일 조금 오른다. 경쟁 무리 사이에서는 원한이 조금 쌓인다. |
| 외톨이 | 긴장이 오르고, 소원 압력(탈출)이 조금 더해진다. 소외가 동기가 된다. |
| 살인 동기 | 무리원을 지키려는 동기(`protect`) +0.1. 무리를 떠난 사람을 향한 질투. |
| 심판 투표 | 무리원은 서로를 찍지 않는다(보호). 리더의 판단 쪽으로 기운다(+0.4). |
| 토론 | 무리원이 지목되면 다른 무리원이 항의하는 대사를 한다. |
| 민혁 | 한 무리와 친밀도가 높으면 초대받는 쪽(안쪽)이 된다. 중립도 선택할 수 있다. |

## 3. 모임 — 주민이 제안하고, 각자 판단한다

기존 `Grammars.Host`(모임 7종: 차·카드·연주·낭독·파티·발표·상영)를 이렇게 넓힌다.

1. **제안하는 자리**
   - 식탁에서 말로 제안한다: "오늘 저녁 {act}, {place}에서 할 건데 올 사람?"
   - 민혁과 대화할 때 초대한다.
   - 초대장을 방문 앞에 둔다(기존).
2. **대답에 이유가 붙는다.** 수락·거절이 대사로 나온다.
   - "좋아, 갈게."
   - "{t} 오면 안 가."
   - "오늘은 쉴래. 무서워서."
   - "리더가 안 간대서."
3. **파벌 모임**
   - 무리가 공지 없이 따로 모인다. 무리원만 안다.
   - 그 시간 서로의 알리바이가 된다. 무리가 무리원을 감싸는 거짓 알리바이가 될 수도 있다.
4. **모임 장면**
   - 민혁이 가면 주최자의 여는 말과 손님들의 말이 나오고, 민혁이 한마디 한다.
   - 축제 장면과 같은 구조다.

## 4. 저택 행사 — 크고, 살인이 노리기 좋은 판
- 조용한 날(2일차부터)에 저택이 저녁 행사를 연다. 사다리 단계와도 겹친다.
- 참석은 각자 판단한다: 두려움, 관계, 누가 오는지.

| 행사 | 방 (오너 그림 번호) | 무엇이 벌어지나 | 살인 설계가 읽는 기회 · 트릭 |
|---|---|---|---|
| 연회 | 메인홀·다이닝룸 (공용 01·02) | 건배 순간 저택이 불을 몇 분 끈다 | `joined` + 어둠 → 어둠 속 한 번, 잔(독) |
| 가면무도회 | 메인홀 (공용 01) | 참석자 모두 가면. 목격의 신원 확신이 떨어진다 | 가면 바꿔 쓰기로 알리바이 조작, 목격 오인 은판 |
| 보물찾기 | 기억보관실·시간정지 서고·비밀서고·창고·지하통로 (신비 02·07, 기능 15·04·12) | 저택이 구역을 공개 배정해 사람들이 흩어진다 | 새 기회 `hunt`: 피해자가 혼자 있을 곳·시각이 공개돼 있다 → 매복. 구역 알리바이 |
| 별 관측회 | 관측실·별관측 온실·옥상 (기능 14, 신비 03, 공용 15) | 관측을 위해 불을 끈다. 높은 곳이다 | 어둠, 추락 |
| 밤의 기도 | 잊힌 예배실·예배당 (신비 09, 공용 08) | 촛불만 켜고 모두 눈을 감는다 | 목격 감소(눈 감음), 촛불 소등 |
| 인형극 | 인형 보존실 (신비 10) | 저택이 인형극을 연다 | 시신을 진열장 인형 사이에 두면 발견이 늦어진다 |
| 수조 공연 | 별비 수조실 (신비 15) | 물과 음악 | 소음이 비명을 덮는다(`noise`), 익사 |
| 계약의 만찬 | 계약의 방 (신비 04) | 한 사람의 소원 문장을 식탁에서 공개한다 | 질투·원한 동기(CH05의 행사판) |
| 전화의 밤 | 전화실 (기능 16) | 저택 전화가 울리고 메시지가 온다 | 통화로 알리바이, 녹음으로 가짜 알리바이 |

## 6. 구현 순서와 파일

| 순서 | 작업 | 파일 |
|---|---|---|
| 1 | 파벌: 계산, 저장, 초대·수락·관계 흐름·외톨이·투표 보호, 식탁 주제 | `Sim/Life/Factions.cs`, `GameState`, `Grammars.WouldAccept`, `LifeTable`, `DebateEngine.DebateVoteOf` |
| 2 | 저택 행사: 연회·가면무도회·보물찾기·별 관측회·밤의 기도, 공지·장면·대사, 살인 기회(`joined` 어둠, `hunt`, 가면 목격) | `Sim/Life/HouseEvents.cs`, `InitiativeDesign.Moments`, `Perception`(가면) |
| 3 | 주민 모임 장면과 식탁의 제안·수락 대사 | `Grammars`, `LifeFest`/`LifeTable`, 대사 |
| 4 | 심판 연결: 파벌 항의, 가면 오인 은판, 구역 알리바이 은판 | `DeckBuild`, `DebateTheories` |
| 5 | 새 방 종류와 배경 카드 | `WorldTypes`, `LayoutGenerator`, Game |

각 단계는 `premise`·`life`·`campaign`·`debate` 회귀와 세이브 동일을 확인한 뒤 커밋한다.

| 행사 | 방 | 시각 | 살인 기회 | 심판 단서 |
|---|---|---|---|---|
| 인형극의 밤 | 인형의 방 · 소극장 | 20:00, 60분 | 객석 소등(어둠 속 습격) | — |
