# 챕터 사건 결과 원장 — 2026-09-25

v2.2 통합 명세의 최초 결과 기준 판정, 공유 피해 예산, 복수 독립 실행 규칙을 위한 기반이다. 본편 사건 자동 생성 완료를 뜻하지 않는다.

## 적용

- 챕터 시작 인원을 고정해 예산을 계산한다. 7명 이상은 2, 4~6명은 1, 3명 이하는 0이다. 사망 결과와 진행 중 예약이 같은 예산을 쓴다.
- 서로 다른 실행자의 예약을 허용한다. 같은 피해자 중복 예약과 서로 실행자/피해자가 되는 미지원 인과 조합은 원인 실행 전에 거절한다.
- 원인 시각, 안정 순번, 예정 시각, 결과 시각, 예약 해제 사유를 별도로 저장한다. 원인 이전 철회와 실제 위험 해소는 예산을 반환하지만 원인 기록을 지우지 않는다. 실제 구조 행동과 구조 UI는 아직 연결되지 않았다.
- 한 tick의 결과 콜백을 모두 처리한 뒤 최초 결과를 고정한다. 결과 시각이 같으면 원인 실행 시 부여한 순번을 쓴다. 발견 순서나 결과 콜백 순서를 사용하지 않는다. 이미 닫힌 tick에 늦게 온 결과 콜백은 주민 상태를 바꾸기 전에 거절한다.
- 런타임 판결의 실제 판정 대상은 이 원장에서 읽는다. 정산의 사건 사망자는 현재 챕터의 결과만 사용하고 다음 챕터에서 새 예산을 시작한다.
- 새 관측 수신 ID에는 사건 ID를 포함해 여러 사건의 수신 번호가 충돌하지 않는다. 본인에게 실제 발생한 관측만 가져오는 경계는 유지한다.

## 저장

새 저장은 원장을 세계 상태와 함께 보존한다. 원인/결과 세계 이벤트와 인물 상태가 맞아야 복원된다. 이전 단일 사건 저장은 기존 원인·예약·결과 이벤트에서 원장을 재구성한다. 숨은 원인이나 새 관측을 생성하지 않는다. 보완된 이전 저장 검사에서는 재구성 결과를 실제 이력과 대조한 뒤에만 반영한다.

## 검증 범위와 남은 연결

EditMode v7b 114/114, 전체 PlayMode v7 44/44(739.6초)가 통과했다. 전체 흐름은 명시적 X31 TestOnly 사건의 물리 접촉, 지연 결과, 신고, 확인, 지역 안내, 조사, 17명 실제 소집·착석, 판결·정산, 다음 챕터·완료 기록 저장/로드다. 두 독립 사건의 동시 진행과 중간 저장은 작은 도메인 물리 어댑터에서 검사했다. 이를 실제 저택 복수 사건의 전체 흐름으로 세지 않는다.

v8에서는 사건 모음과 복수 신고 대기열·유스티 확인·추가 공표·복수 사건 전말을 런타임에 연결했다. 실제 런타임의 역순 신고와 확인 중 저장/복원 검사는 통과했으며 상세 범위는 `CaseCollection_20260925.md`에 기록한다. 전체 PlayMode v8은 48/48 통과했고 단일 X31 실제 접촉→다음 장 흐름을 유지했다. 작업 폴더의 옛 collection/schedule 초안은 이제 설치된 소스보다 오래됐으므로 다시 복사하지 않는다.

항상 같은 공개 안전 점검, 본편 사건 문법/자율 계획, NPC 신고, 같은 실행자의 복수 피해자 묶음은 여전히 후속 통합 대상이다. 일반 플레이의 X31 자동 등록은 계속 꺼져 있다.
