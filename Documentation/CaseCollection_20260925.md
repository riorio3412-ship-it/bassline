# v8 복수 사건 연결

런타임이 사건 배열을 소유한다. 신고 대상은 실제 클릭한 시신과 개인의 발견 기록으로 결정하고, 유스티는 전달받은 발견 위치로 이동해 물리적 거리·시야 안에서 확인한다. 별도 신고는 대기열에 유지된다. 공표 시간표는 확인 후 실제 공표한 사망에만 반응한다. 첫 공표 60분, 추가 공표 시 max(기존 예정, 추가 공표+30분)를 한 번 적용한다. 숨은 피해 예약은 이 시간표의 입력이 아니다.

저장에는 사건 배열, 현장 확인 대상, 신고 대기열, 공표 이력을 포함한다. 기존 단일 사건 저장은 배열로 이행하며 호환용 첫 사건 필드와 일치 여부를 검사한다. 재판은 공용 원장의 최초 결과 대상 한 명을 판정하고, 함께 닫힌 두 사건의 허용된 전말을 공개·보관한다.

`BL22_MultipleReports_v8.xml` 1/1 통과: 두 결과를 명시적으로 기록한 TestOnly 장면에서 B를 먼저 발견·신고하고 확인 도중 저장/복원한 뒤 A를 신고했다. 실제 런타임의 유스티 이동/확인, 두 공표와 개별 수신 보고, 신고 순서와 무관한 최초 결과 판정 유지, 전체 저장 복원을 확인했다. 초기 결과·플레이어 위치는 시험용 배치다. 두 자율 원인 행위, 플레이어의 자연 이동, 두 사건의 실제 착석을 검증한 것으로 세지 않는다.

일반 플레이의 X31 자동 등록은 계속 꺼져 있다. 본편 사건 문법, NPC 신고, 동일 가해자 복수 피해 묶음, 모든 재판 전 동일한 공개 안전 점검, 숨은 미확정 사건이 있는 소집의 전체 정책, 조기 소집 규칙은 별도 미완료 항목이다.

전체 `BL22_PlayMode_v8.xml`은 48/48 통과했다(1,800.0초). 그중 기존 단일 X31의 물리 접촉→발견→신고→확인→60분 수사→17명 수신/실제 착석→표결→정산→다음 장→완료 아카이브/저장 검사는 1,501.7초로 통과했다. 역순 복수 신고 검사도 이 전체 실행에 포함해 통과했다. 두 시험의 초기 조건과 범위는 서로 다르므로 이를 복수 자율 사건 전체 플레이로 합쳐 주장하지 않는다.
