# BASSLINE 0.18 작업 기록

## 이번 변경

통합기획서 MAIN 71–72쪽의 IG01 생활 예제를 이어서 구현한다. 작업실의 공용 반납대와 별도로 태겸의 개인 가방과 메모를 배치했다. 메모를 가까이에서 끝까지 살펴본 뒤에만 `이 메모, 반납 장소 얘기야?`를 물을 수 있다. 태겸은 자신의 정리 순서를 적은 메모라고 설명하며, 빌린 펜은 직접 건네 달라고 답한다. 반납 안내는 세 줄의 짧은 대사로 정리했다.

가방 앞에 놓기와 다시 집기는 실제 손을 뻗는 동작, 원래 펜의 소지권 이전, 충돌 검사와 중간 저장을 사용한다. 가방 앞에 놓아도 대여는 끝나지 않으며 민서의 공용 반납대 수거 대상에도 포함되지 않는다. 태겸이 못 본 이동을 원격으로 알게 하지 않는다.

태겸이 직접 펜을 받은 후, 실제로 들은 반납 안내 또는 확인한 혼동의 경로를 근거로 배운 점을 개인 노트에 남긴다. 잘못된 비난을 했다면 그 말을 끝까지 들었던 사람들에게 실제로 정정해야 한다. MAIN 32쪽의 고유 학습 보너스 범위 안에서 10 EXP를 프로필에 한 번 반영한다. 회차 저장보다 프로필 보상 원장을 먼저 원자적으로 기록하고, 이전 저장으로 돌아가도 중복 지급하지 않는다. 이 10 EXP는 IG01 전체 기본 보상·스킬 트리·무료 노드 해금 완료를 의미하지 않는다. 사망 사건이나 재판 등급을 생성하지 않는다.

## 확인 중 발견한 문제

첫 PlayMode 검사 `BL22-v18-loan1.xml`은 30개 중 28개 통과, 2개 실패했다. 플레이어가 들은 NPC의 완전한 발언은 실제 발화자의 원문에서 수신된 기록이다. 학습 조건이 직접 관찰만 조회하면서 이 수신 기록을 누락해 정상적인 반납 뒤에도 배운 점을 남기지 않았다. 관찰 근거와 발언 수신 근거를 별도로 검사하도록 수정했다. 발언은 원문 발화 시각과 플레이어의 실제 수신 시각이 맞아야 하며 중간에 끊긴 말은 완전한 안내로 계산하지 않는다.

## 범위와 남은 작업

새 가방은 임시 조형이다. 이번 변경으로 전체 아트, 생활 의뢰 36개, 사건 변주, 성장/스킬 전체 구현이나 IG01의 모든 연출을 완료 처리하지 않는다. 자연스러운 저택 탐색의 발견 가능성과 이동 동선은 별도 플레이 검증이 계속 필요하다. Windows 화면 검사에서 플레이어만 검사 위치로 배치하는 경우 이를 TestOnly로 명시하며 NPC를 이동시키거나 원격 지식을 주입하지 않는다.

## 동작과 빌드 확인

`BL22-v18-final.xml`: PlayMode 40/40 통과, 98.82초. 기존 관련 검사 34개와 새 검사 6개다. 실제 읽기를 끝내기 전 질문 비노출, 개인 가방의 소지/저장/수거 제외, 직접 안내 경로, 공용 반납 혼동 후 모든 실제 청자에 대한 정정, 프로필 1회 보상과 레벨 경계, 저장 실패 후 소지 보존과 재시도, 근거를 바꾼 학습 저장 거부를 포함한다. 같은 검사의 재실행을 별도 통과 수로 더하지 않는다.

`BL22_v18_build2.log`: Windows 빌드 성공, 오류 0, 경고 2, 25.54초. 최종 화면 검사 결과는 확인 후 아래에 기록한다.

첫 Windows 화면 검사 `BL22-v18-smoke1`은 개인 메모 장면 전에 대여 손동작이 취소되어 실패했다. 실제 중간 화면에 여러 NPC가 전달 위치로 모였고, 게임은 팔 공간 부족으로 중단하며 펜을 원 소지자에게 유지했다. 이를 전달 성공으로 간주하지 않았다. 화면 검사 스크립트를 보완해 이런 실제 취소 후 월드 시간을 진행하고 플레이어가 다른 근접 위치에서 대화·전달을 재시도하도록 했다. NPC 이동이나 충돌 무시는 사용하지 않으며 모든 재시도 사유를 결과에 남긴다. 게임의 충돌/소지 규칙 변경은 없다.

`BL22-v18-smoke2`(20260925T190415270Z)는 50개 화면, 런타임 오류 0으로 메모·반납·설정 복원을 통과했다. 720p 선택지와 1080p 세 줄 답변은 직접 열어 확인했다. 반면 세계 화면에서는 메모의 긴 줄이 표지 가장자리에 걸리고 큰 가방 표지가 가방 몸체를 가렸다. 작은 밝은 종이 메모와 가방 전면 이름표로 크기·서체 크기·배치를 수정했다. 씬 생성 버전도 018B로 올려 캐시된 이전 표지가 빌드에 남지 않도록 했다. 이 변경은 글자/장식에만 적용되며 물리 반납 위치와 충돌체는 유지한다.

후속 `BL22-v18-smoke3`(20260925T190655527Z)도 50개 화면과 런타임 오류 0으로 통과했다. 작은 이름표가 가방을 가리지 않고 메모의 긴 줄도 표지에 들어온다. 세계 속 종이의 크기와 조명에 의존하지 않고 읽을 수 있도록, 실제 상호작용 뒤 크게 펼쳐지는 읽기 화면도 검사에 추가했다. 개인 메모와 공용 장부의 읽기 화면은 원문·다음 행동 안내·뒤로만 보여준다. 이 단계에서 가설 생성이나 근거 분류 메뉴를 요구하지 않는다.

읽기 화면을 추가한 `BL22-v18-smoke4`는 해당 화면에 도달하기 전 기존 CH_04 대화 검사에서 멈췄다. 그 순간 이동 중인 인물 주변에 플레이어를 배치할 수 있는 유효한 근접 위치가 없었다. 초기 대화 검사도 최대 1,800 월드 틱 동안 인물의 실제 이동을 기다리고 근접 위치를 다시 찾도록 보완했다. 가까이 갈 수 없는데 대화를 강제로 허용하거나 검사를 통과시키지 않는다.

## 최종 실행 확인

최종 `BL22_v18_build7.log`: Windows 빌드 성공, 오류 0, 경고 2, 24.29초. `BL22-v18-smoke5`(20260925T191321196Z): PASS_SMOKE_ONLY, 1280×720·1920×1080 합계 52개 화면, 런타임 오류 0, 개인 메모 경로·실제 대여/반환·개인 노트의 학습 기록·설정 복원을 통과했다. 메모를 실제 상호작용으로 읽고 자동으로 열린 원문 화면을 두 해상도에서 직접 열어 확인했다. 원문과 안내가 잘리지 않고 ‘뒤로’만 표시된다.
