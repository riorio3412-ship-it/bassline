# BASSLINE 0.20 작업 기록

김진우 모델의 팔꿈치에서 소매가 갈라지고, 옆모습에서 입과 얼굴 선이 떠 보이는 문제를 수정한다. 0.19에서 실제 렌더로 확인한 품질 문제를 후속 제작으로 처리하는 작업이다. 전체 게임·모델·UI 범위는 유지한다.

## 소매와 얼굴

소매는 위팔/아래팔의 독립된 단단한 메시 두 개에서 하나의 닫힌 메시로 바꿨다. 각 소매는 1,150개 정점과 위팔·아래팔·옷 전용 중간 관절을 쓰는 SkinnedMeshRenderer이며 정점당 최대 2개 가중치를 혼합한다. 옷 전용 관절은 실제 팔꿈치의 위치와 두 팔뼈의 중간 회전을 따른다. 손목 쪽은 기존 아래팔에 붙어 있다. 원래 팔 길이, ActorArmRig의 도달 판정, 손잡이 위치, 충돌체와 소지권 이전은 변경하지 않는다.

눈·눈동자·눈꺼풀·눈썹·입과 의복의 접힌 선은 실제 얼굴/의복 삼각형 표면 위에 투영한다. 표면 곡률을 별도의 타원으로 추정해 붙이던 차이와, 측면에서 떠 보이는 선을 줄였다. 겹친 눈꺼풀과 흰자에는 다른 깊이를 사용해 깜빡이는 겹침을 줄인다. 목의 셔츠 깃 받침을 추가했다. 카디건의 앞섶 폭 변화가 옆면 정점까지 비틀지 않도록 옆·뒤 정점 각도를 고정했다.

구현 참조: [Unity Mesh.bindposes](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/mesh/bindposes). 바인드 자세와 뼈 배열의 순서를 맞추고 각 뼈의 역행렬을 모델 공간에 대응시킨다. 문서 확인은 실행 검증과 별도다.

## 실제 렌더에서 확인한 문제

초기 배치 검토에서는 새 손 자세에 비해 소매가 이전 자세로 표시됐다. 정지된 편집기에서 연속으로 카메라 렌더를 요청하면 그 사이 일반 애니메이션 프레임이 없기 때문이다. 검토 도구가 Unity BakeMesh로 현재 관절의 실제 변형 메시를 매번 계산하고, 임시 렌더 메시와 원래 스킨 표시를 복원하도록 변경했다. 생성된 2D 콘셉트 그림을 3D 검증 화면으로 대신 사용하지 않는다.

실행 파일의 별도 검사에서는 월드 시간을 잠깐 멈추고 기존 손 리그에 검토용 자세를 넣은 뒤 실제 게임 프레임에서 표시한다. 이 장면은 `jinwoo_sleeve_pose_testonly`로 구분하며 원래 관절 회전을 복원한다. 자연스러운 물건 전달 전체, NPC의 자율 행동 또는 애니메이션 완성도를 입증하는 것으로 세지 않는다.

첫 PlayMode 검사 `BL22-v20-first.xml`은 45개 중 44개 통과, 1개 실패했다. 두 뼈만 혼합한 소매의 안쪽 모서리가 강한 굽힘에서 원래 길이의 15% 아래로 눌렸다. 판정 허용치를 낮추지 않고 옷 전용 중간 관절과 혼합 구간을 추가했다. 실행 화면에서 보인 카디건 옆의 작은 삼각형은 안쪽 바지 허리의 관통으로 확인해 바지 상단의 폭과 배치를 조정했다.

## 검증과 미완료 범위

새 검사는 소매가 닫힌 연결면인지, 실제 변형 후 팔/손목 연결이 유지되는지, 몸의 방향과 팔 자세가 달라져도 모서리가 과도하게 늘어나거나 무너지지 않는지 확인한다. 인물 기록의 중립 포즈가 원래 NPC의 관절을 참조하거나 원격 자세를 노출하지 않는지도 확인한다. 최종 결과는 실행 후 아래에 기록한다.

이번 변경은 Humanoid 전체 리그나 얼굴 표정 리그를 완료한 것이 아니다. 공통/고유 애니메이션 전체, LOD, 4재질 아틀라스, 원본 모델 교환 파일, 머리·얼굴 조형과 2D 일치도는 계속 남아 있다. 목과 어깨 비율·자연스러운 옷 주름도 추가 미술 검토 대상이다. MODELS/ANIMATION의 provisional_geometry 상태를 유지한다.

## 최종 확인

- `BL22-v20-final.xml`: PlayMode 45/45 통과, 108.96초. 기존 관련 43개와 새 소매 변형/중립 프로필 검사 2개다. 몸의 방향 2종과 팔 자세 3종에서 양팔을 확인했다. 첫 실패와 재실행을 별도 테스트 개수로 더하지 않는다.
- `BL22_v20_build2.log`: Windows 빌드 성공, 오류 0, 경고 4, 22.85초. 기존 인물 UI의 deprecated FindObjectsSortMode/FindObjectsByType 경고가 각 빌드 단계에서 반복됐다.
- `BL22-v20-smoke2`, RunId `20260925T195255781Z`: PASS_SMOKE_ONLY, 1280×720·1920×1080 합계 56개 화면, 런타임 오류 0. 실제 프레임의 소매 변형, 새 모델/스탠딩, 메모·대여/반납, 설정 복원을 확인했다. 굽힌 소매와 일반 자세, 중립 인물 기록을 직접 열어 확인했다.
- `Verification/ArtV20`: 정면·사선·측면·후면·얼굴·굽힌 자세·소매 근접 렌더. `render-source.txt`에 제작 코드 SHA256을 기록한다. 이 스튜디오 렌더와 실제 실행 화면의 증명 범위는 다르다.

배포 폴더는 outputs/BASSLINE_v0.20이다. 이전 실행 빌드를 유지하며 복사 파일과 SHA256 비교는 Verification/BL22-v20-delivery.json에 남긴다. 자동 검사와 이번 부분 개선을 최종 아트 품질이나 전체 게임 완성으로 간주하지 않는다.
