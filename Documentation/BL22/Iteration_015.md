# 0.15 — 공용 반납대, 실제 수거와 정리 기록

2026-09-26. 직전 0.14는 인물 조형과 실행 검증의 진전이었다. 이번에는 통합 기획서 71–72쪽 IG01/TEST-LIFE01의 빠진 물건 이동 경로를 본편에 연결했다. 전체 기획 범위는 유지한다.

## 실제 구현

작업실의 기존 작업대에 공용 반납대·탁상 정리함·정리 장부를 배치했다. 표지판에는 개인 물건은 주인에게 직접 돌려주고, 남은 물품은 정리함과 장부에서 확인할 수 있다고 적었다. 기존 보행망과 작업대의 물리 충돌을 유지한다. 작은 수납 가구는 기능 검증용 조형이며 최종 환경 아트가 아니다.

플레이어는 실제로 빌린 펜을 반납대에 내려놓을 수 있다. 손이 이동하고 90틱에 소지가 바뀐 뒤 120틱에 손을 거둔다. 공간/팔/물건 경로를 확인하며, 이동이나 Esc로 중단할 수 있다. 내려놓기만으로 대여를 반환 완료로 바꾸지 않는다.

민서는 펜의 원격 위치를 조회해 곧바로 달려오지 않는다. 다른 일정과 활동이 비었을 때 주기적으로 반납대를 확인한다. 가까이 도착해 실제로 확인한 펜을 수거하고, 원래 물건을 손에 쥔 채 보행망과 CharacterController로 다른 작업대의 정리함까지 이동한다. 도착해 손으로 보관을 완료한 뒤 180틱의 기록 작성 시간을 거쳐 장부를 남긴다. 걷기/손 이동과 달리 펜으로 글씨를 쓰는 최종 손동작은 아직 제작하지 않았다.

장부는 수거·보관·작성 시각과 원물 특징을 담는다. 플레이어에게 자동 전달하지 않으며 가까이 가서 읽어야 한다. 닫힌 정리함의 물건은 렌더와 일반 관측에서 숨긴다. 공용 정리함은 민서와 대화하지 않아도 열 수 있으며 원래 펜을 살펴보고 꺼내 태겸에게 직접 반환할 수 있다.

태겸에게 ‘펜 돌려받았어?’, 민서에게 ‘반납대에 있던 펜 봤어?’라고 물을 수 있다. 답변은 본인이 경험한 전달/수거/보관 기록을 사용한다. 대여 중에는 대화 첫 화면에 ‘빌린 펜 이야기’를 표시해 반복 메뉴 이동을 줄였다. 발언은 기존 실제 발화·청취·부분 수신 체계를 통과한다.

이동 동작의 커서·소지 전환·정리 작업 단계·장부·서랍 개방 상태를 저장한다. 손에 든 물건의 권위 위치도 매 틱 실제 손/전달 위치를 따라가도록 보완했다. 이전 저장에 공용 정리 상태가 없으면 기본 상태로 시작한다.

## 검증 기록

- 첫 장면 생성에서 새 컴포넌트의 using 누락으로 컴파일 오류가 발생했다. 누락을 수정하고 이후 생성/테스트를 실행했다. 실패 로그도 보존한다.
- `BL22-v15-common-return1.xml`: 새 PlayMode 3/3 통과. 중간 저장과 원 소지 복원, 공용 수거/운반/보관/원물 회수, 중단 전후 소지 단일성을 확인했다.
- `BL22-v15-exchange2.xml`: 새 검사와 기존 대여 검사 17/17 통과. 팔 공간 검사를 강화한 뒤 회귀 확인했다.
- `BL22-v15-exchange3.xml`: 18/18 통과. 장애물과 원격 정리함 접근 거부, 장부와 원물 확인 뒤 기존 대화 버튼을 통한 최종 직접 반환을 포함했다.

검사에서 플레이어와 민서의 최초 위치 배치는 테스트용으로 명시한다. 민서의 반납대→정리함 이동은 실제 보행이며 매 틱 변위 상한을 검사한다. 자연 플레이에서 모든 시작 위치·모든 문/군중·거절 변형을 검증했다는 뜻은 아니다. 최종 수정 이후의 검사 및 Windows 화면 결과는 아래에 추가한다.

`BL22-v15-exchange-final.xml`은 18/18 통과했다. 최종 수납 위치와 손/물건의 위치 동기화를 적용한 뒤 운반 도중 저장·불러오기와 현재 손 위치 일치도 검사했다. 기존 물건 전달 검사 14개와 새 공용 정리 검사 4개이며, 이전 검사와 합산해 고유 검사 수를 부풀리지 않는다.

첫 Windows 화면 검사 `BL22-v15-smoke1`은 32개 캡처 뒤 계단에서 펜이 난간에 닿아 접근을 취소하면서 FAIL이었다. 원래 소지자는 유지됐고, 실제 물리 제한을 통과시키도록 수정하지 않았다. 화면 검사만 이 정상 중단을 별도로 기록한 뒤 실제 월드 틱을 진행해 NPC가 이동하기를 기다리고, 테스트용 플레이어 위치를 바꿔 재시도하도록 보완했다. 최대 8번으로 제한하며 실패 원인과 재배치 내역을 결과에 남긴다. NPC를 이동시키거나 장애물을 지우지 않는다.

`BL22-v15-smoke2`는 44개 캡처/PASS_SMOKE_ONLY/실행 오류 0이었다. 전달 접근 취소 1회를 별도로 기록하고 정상 대여·반환을 마쳤다. 실제 대화 화면에서 대여 전의 ‘펜 돌려받았어?’가 불필요하게 보이는 것을 발견해 숨겼다. 허락 직후에는 ‘펜 받기’, 반환 가능 시에는 ‘빌린 펜 돌려주기’를 먼저 표시하고, 이미 허락받았거나 빌린 상태의 중복 대여 질문을 숨겼다. 이에 맞춰 화면 검사도 아직 유효한 허락을 다시 묻지 않고 받기를 선택하도록 수정했다.

## 최종 UI 확인 중 발견한 문제

`BL22-v15-ui-final.xml`은 실제 선택지 정리 이후 18/18 통과했다. `BL22-v15-smoke4`(20260925T172449034Z)는 44개 캡처, 실행 오류 0, 실제 대여·직접 반환 및 설정 복원 확인으로 PASS_SMOKE_ONLY였다. 접근 중 장애물 접촉 1회는 소지를 유지하며 취소된 뒤 재시도했다. 앞선 smoke3은 결과가 RUNNING으로 남아 있어 성공 근거에서 제외한다.

공간 화면 검사 space1/space2는 검사 진입 조건과 첫 안내 화면 처리 누락으로 실패했다. 검사 도구의 진입 처리를 바로잡은 space3은 20개 캡처를 만들었지만, 이미지를 직접 확인하니 공용 안내문이 반대로 보이고 지나치게 컸다. 자동 화면 생성 성공은 시각 품질 합격을 뜻하지 않는다. 작은 고정 크기 글씨와 어두운 표지판 바탕으로 수정했다. 첫 수정 빌드에서는 장면 생성 캐시 때문에 옛 표지가 남아 있는 것도 확인해 장면 버전을 015D로 올려 재생성했다.

015E에서 표지판을 물건과 수납함 뒤로 옮겼다. `BL22-v15-space6`(20260925T173131189Z)은 1280×720과 1920×1080의 공간 캡처 총 20개를 생성했고 실행 오류 없이 종료했다. 반납대와 정리함의 실제 이미지를 열어 방향·글씨 크기·수납 공간 가림을 확인했다. 환경의 재질·조명·소품은 여전히 임시이며 최종 아트 합격이 아니다. 최종 Windows 빌드7은 오류 0/경고 2, 16.16초로 성공했다.

## 계속 남는 범위

최종 실행 파일의 `BL22-v15-smoke5`(20260925T173149859Z)는 주요 화면 44개 캡처와 실제 대여·반환 확인을 마쳤다. 실행 오류 0, 사용자 조작 설정 복원 확인, PASS_SMOKE_ONLY이다. 이 화면 검사는 공용 수거 전 과정을 자연 플레이로 검증한 결과가 아니며, 해당 기능은 앞서 명시한 18개 PlayMode 검사 중 새 검사 4개가 다룬 범위에 한정된다. 출력 폴더에는 이 빌드의 실행 파일과 필요한 데이터 전체를 복사하고 SHA-256으로 비교한다. 이전 버전은 그대로 보존한다.

IG01 전체 완료로 표시하지 않는다. 사적 메모를 잘못 읽는 변형, 명확한 지시/무지시/메모 오독의 세 조건 검증, 실제 잘못된 주장과 그 정정, 중재·관계 변화·학습 1회 결과가 남아 있다. 정리 담당자의 중단/사망/장시간 통로 막힘 및 다양한 물건을 처리하는 일반 체계도 확장해야 한다.

비살상 물건 오해를 살인 재판/처형으로 만들지 않는다. 최종 인물·환경·동작·음향·전체 대사, 나머지 사건 문법과 반복 플레이, 모든 릴리스 기준은 기존 전체 제작 목표에 계속 포함한다.

최종 전달 결과: outputs/BASSLINE_v0.15에 347개 실행·데이터 파일을 복사했고 전부 SHA-256이 일치했다. Verification/BL22-v15-delivery.json에 각 파일의 해시와 검증 실행 ID를 보관했다.
