# 0.13 — 팔·손 접촉과 물건 전달 동작

2026-09-26. 전체 게임 제작의 중간 단계다. 직전 턴은 0.12 실행 화면 확인·배포 기록 정리로 진전이 있었다. 기존 전체 범위와 원문 147쪽/인수 항목 109개를 유지한다.

## 이번 변경

기존 절차 생성 인물의 팔이 몸통 정적 메시로 합쳐져 있던 구조를 분리했다. 어깨·팔꿈치·손목·손바닥·손가락을 작성하고, 물건을 붙이는 지점을 실제 손목 아래의 그립으로 연결했다. 인물 18명의 팔 구조를 만들되 플레이어는 1인칭 팔만 표시한다. 유스티는 이번 팔 변경 대상이 아니다. 두 뼈 길이는 고정되고, 손이 닿지 않는 거리는 모델을 늘려 맞추지 않는다. 이것을 최종 19인 모델이나 94개 완성 애니메이션으로 세지 않는다.

펜 대여/반환은 NPC가 CharacterController 충돌과 바닥을 확인하며 약 0.82m 거리까지 접근한 뒤 시작한다. 플레이어 위치를 자동 이동시키지 않는다. 양손은 60틱 동안 펜의 서로 다른 지점으로 접근해 90틱까지 함께 접촉하며, 90틱에 실제 소지가 바뀌고 120틱까지 손을 거둔다. 장애물·손의 도달 범위·팔 공간·소품 경로를 검사한다. 접근 중 막히거나 시간이 초과되면 물건을 넘기지 않는다.

동작 중 시선을 돌릴 수 있고 몸 방향은 전달 자세에 유지된다. 이동 입력/Esc 취소·메뉴 정지·중간 저장을 유지한다. 접근 틱, 접촉 지점, 양쪽 손의 시작/종료 위치와 몸 방향을 저장한다. 0.12의 기존 진행 중 전달은 구버전 커서로 읽으며 새 대여부터 접촉 동작을 사용한다. 실제 전달 사건 시각은 접근 시간과 접촉 커서를 모두 반영해 검증한다.

프로필용 모델 복제는 팔도 중립 자세로 복원하여 원격 인물의 소지 자세를 노출하지 않도록 했다. 노트의 물건 위치 판정은 발의 좁은 높이 범위와 분리했다. 실제 방 높이와 층, 서재 원형 공간·낮은 바닥, 회랑의 비어 있는 중앙 공간을 구분한다. 기존 기록은 소급해서 고쳐 쓰지 않는다. 물건 반환 관계 기록도 실제 행동에 맞는 문구로 바꿨다.

첫 실행 화면 검토 뒤 손가락을 두 마디로 나누었다. 받는 손은 접근에 따라 굽히고, 건넨 손은 동작 끝에 편다. 받은 물건을 기본 1인칭 시야에서도 볼 수 있도록 플레이어의 소지 자세를 높였다.

## 검증

- `BL22-v13-item-exchange.xml`: 기존 대여 PlayMode 검사 9/9 통과.
- `BL22-v13-contact.xml`: 21개 중 20개 통과. 실패는 접근 속도 검사에서 캡슐의 바닥 안착 수직 이동까지 평면 이동량으로 합한 검사 문제였다. 실제 수직 이동과 수평 이동을 각각 검증하도록 고쳤다.
- `BL22-v13-contact-final.xml`: 21/21 통과. 대여 검사 13개와 기존 발화/기록 UI 검사 8개. 매 전달 틱의 소지자 손-펜 거리, 양손 접촉, 뼈 길이, 접근 중 저장, 손을 뻗은 자세 복원, 시선 이동, 가구 앞 접근 취소를 포함한다.
- `BL22-v13-room-volume.xml`: EditMode 3/3 통과. 층간 슬래브 제외, 손 높이·다른 층·작은 방 우선, 원형 서재·회랑 내부 구분. 전체 80개 방의 모든 부피를 검증했다는 뜻은 아니다.
- `BL22-v13-incidents.xml`: EditMode 12/12 통과. 기존 사건 원인/결과·예약·저장 변환 검사.
- `BL22-v13-hands-final.xml`: 손가락과 플레이어 소지 자세 변경 후 PlayMode 16/16 통과. 대여 검사 13개와 실제 달리기/걷기·중첩 정지·저장 복원, 초기 인물/방 연결, 부재 인물의 새 관측 방지 검사 3개.
- `BL22-v13-passerby.xml`: PlayMode 14/14 통과. 허락을 받은 뒤 다른 인물이 시야를 가려도 받기 메뉴는 유지되며, 실제로 그 인물을 통과해 펜을 넘기지는 못하는 검사를 추가했다.

위 검사들은 범위가 겹치므로 합산하여 고유 검사 수로 표시하지 않는다. Windows 화면 검토 결과는 아래에 추가한다.

첫 화면 검사 `BL22-v13-smoke1`은 42장/PASS_SMOKE_ONLY/런타임 오류 0이었다. 실제 이미지에서 손-펜 접촉과 물건의 중앙 홀 위치 표시를 확인했지만 손가락이 펴져 있어 조형을 보완했다. 이후 `BL22-v13-smoke2`는 태겸 주변에 유효한 대화 촬영 위치를 찾지 못해 FAIL이었다. 실패 결과를 보존하고, 화면 검사가 NPC 위치를 바꾸거나 충돌/시야 제한을 무시하지 않도록 실제 월드 틱을 최대 1800틱 진행하며 재접근하도록 했다. 이 제한 내에도 만나지 못하면 위치·활동 진단을 포함해 실패한다. 테스트 전용 플레이어 프레이밍은 계속 명시한다.

`BL22-v13-smoke3`에서는 허락 발화 뒤 다른 인물의 시야 차폐 때문에 받기 버튼이 숨겨지는 실제 UI 결함을 발견했다. 가까이서 들은 대여 허락/메뉴의 조건을 실제 전달 접촉 조건과 분리했다. 벽을 통과한 발화나 원격 수신을 허용하지 않으며, 캐릭터 접근·팔·펜의 물리 차폐는 그대로 적용한다. 대화 도중 다른 사람이 끼어들었다는 이유만으로 이미 들은 허락이 사라지지 않는다.

`BL22-v13-smoke4`에서는 240틱(4초)의 실제 생활 진행 뒤 태겸과 만나 대여·반환을 마쳤다. 손가락 접촉과 받은 펜의 기본 시야 노출을 실제 이미지로 확인했다. 44개 캡처가 모두 PNG 검증을 통과했으나, 기존 검사기가 여전히 42장만 기대하여 최종 상태는 FAIL이었다. 보고서는 그대로 보존했고, 22개 화면 단계별로 두 해상도가 각각 한 장씩 존재하는지 검증하도록 검사기를 수정했다. 단순히 실패 보고서의 상태를 바꾸지 않았다.

## 계속 필요한 작업

현재는 교체 가능한 절차 생성 모델/팔이다. 2D 스탠딩과 일치하는 최종 인물 조형·의상 변형, 자연스러운 어깨·손가락 애니메이션, 도중 취소의 부드러운 복귀, 다양한 크기의 물건별 그립이 필요하다. 물건 전달의 공통 체계를 펜 외 물건과 NPC끼리의 행동으로 확장해야 한다. 모든 소품의 Rigidbody·파손·마찰·낙하·전체 이력 또한 미완료다.

IG01 공용 반납대·민서의 수거/서랍 보관·오해 정정과 세 변형, 본편 자율 사건, 전체 챕터 규칙과 생활 콘텐츠, 최종 환경·대사·UI 가독성·릴리스 검증은 계속 남아 있다. 이번 동작 검사와 실행 빌드는 최종 게임 완료를 뜻하지 않는다.

## 최종 빌드와 배포

최종 `BL22_v13_build6.log`의 Windows 빌드: Unity 6000.6.0f1 / Succeeded / Errors=0 / Warnings=2 / 22.66초.

최종 `BL22-v13-smoke5/mansion-smoke.json`: 실행 ID `20260925T161837726Z`, `PASS_SMOKE_ONLY`, 22개 화면×2해상도=44개 캡처, 런타임 오류 0, LoanExchangeVerified=true, ControlsPreferencesRestored=true. 태겸의 실제 이동을 60틱 기다린 뒤 접근했다. 캡처 이미지에서 양손-펜 접촉, 손가락 굽힘, 기본 시야의 소지 펜, 반환 상태 및 물건의 방 이름 표시를 직접 확인했다.

실행 화면 검사에는 테스트 전용 플레이어 프레이밍과 의미 기반 Unity 버튼 호출이 들어 있다. 일부 숨겨진 창 캡처는 SRP 카메라/Canvas 보조 경로를 사용한다. 자연 이동으로 만나는 IG01 전체 이야기, 네이티브 마우스 입력, 성능 벤치마크 또는 최종 아트 승인의 증거로 확대 해석하지 않는다.

`outputs/BASSLINE_v0.13`에 실행 폴더를 복사하고 배포 대상 347개 파일 전부의 원본-복사본 SHA256 일치를 확인했다. Unity의 `BackUpThisFolder_ButDontShipItWithYourGame` 폴더는 제외했다. 기존 0.11/0.12 폴더와 이전 검증 결과는 보존했다.

다음 우선순위는 실제 이미지에서 드러난 과도한 캡슐 앞머리·가려진 눈·정장 형태를 콘셉트아트 기준으로 교체하는 것이다. 노트의 관측 시작 시각과 수신순 정렬이 섞여 보이는 부분도 시간 구간 표기를 검토해야 한다. 전체 범위는 축소하지 않으며 목표는 계속 활성 상태다.
