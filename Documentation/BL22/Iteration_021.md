# BASSLINE 0.21 작업 기록

약속을 제안하자마자 수락·확정되던 본편 동작을 플레이어의 제안과 NPC의 답변으로 나눴다. 사용자의 ‘대화가 어렵고 버튼의 의미를 모르겠다’는 피드백을 우선한다. 통합 기획서 MAIN 69의 기존 레코드 확장 원칙과 MAIN 71의 IG02 ‘바뀐 약속’에 필요한 실제 수신 경계를 연결하는 작업이다.

## 플레이 흐름

대화의 ‘다른 이야기 → 만날 시간 정하기’에서 장소 목록을 직접 고르고 5분/10분 뒤 시각을 선택한다. 이전처럼 ‘다른 장소’를 반복해서 눌러 순환하지 않는다. 선택하면 대화 화면으로 돌아가 민혁이 제안하고 상대가 답한다. 제안과 답변 각각 6초 동안 일반 월드 시간이 흐르며 ‘끝까지 말하기/듣기’의 빠른 진행도 실제 월드 틱을 실행한다.

제안 도중 끊기면 약속은 생성되지 않는다. 제안을 다 듣고 답변 도중 끊기면 미확정으로 남고, 다시 대화할 때 ‘아까 말한 약속, 괜찮아?’로 물을 수 있다. 기존 일정과의 충돌이나 선호에 따라 수락하지 않을 수 있다. 완료한 답변을 플레이어가 모두 들어야 확정되며 대화 옆에 시각·장소·상태를 표시한다. 거절·재협의 요청 자체를 약속 파기나 배신 경험으로 만들지 않는다.

## 상태와 저장

기존 ConversationPlaybackState에 진행 중인 약속 발화의 타입 정보를, SocialLedger의 AppointmentRevision에 제안/답변 원문 참조와 수신 시각을 추가했다. 새 정답 저장소나 NPC 전체 지식 뷰를 UI에 만들지 않았다. 발화 전문과 미확정 NPC 판단은 플레이어 PlaybackView에 노출되지 않는다.

저장 검증은 약속의 시간·장소·참가자와 실제 발언 원문, 상대가 받은 원문의 근원, 수신 시각, 수락 상태를 대응시킨다. 제안 중/답변 중의 저장에서 이어갈 수 있으며 답변 전에 수락 플래그만 넣은 저장은 거절한다. 기존 비발화 방식의 과거 저장은 기존 방식으로 읽는다.

## 검증 기록

첫 전용 PlayMode 검사는 6개 중 5개 통과했다. 저장 복원 뒤 전체 지식 JSON의 숫자 문자열을 비교한 검사가 float 기반 물리 좌표의 끝자리 차이로 실패했다. 두 번째 검사는 좌표를 수치로 비교했으나 1µm 한도에서 약 3.8µm 차이를 확인했다. 대화·원문·시간·근원은 동일하고 물리 좌표는 10µm 이내를 비교하도록 분리했다. 이후 실제 NPC 이동과 원격 만남 기록 방지 검사도 추가한다. 재실행을 별도 기능 수로 합산하지 않는다.

최종 검사와 실행 화면의 결과는 실행 후 기록한다. 네이티브 검토는 인물을 가까이 배치하는 TestOnly 준비 뒤 실제 UI 버튼과 대화/약속 처리로 실행하며, 자연스러운 전체 탐색이나 모든 일정 경로의 완성을 증명하지 않는다.

관련 회귀 52개를 처음 함께 실행했을 때 45개 통과, 7개 실패했다. 6개는 Unity의 인라인 null 객체 복원 때문에 일반 대화에도 빈 약속 객체가 생긴 문제였고, 기존 OptionalObjects에 약속 발화의 존재 비트를 추가해 처리했다. 다른 1개는 검사 준비에서 NPC의 몸 위치만 옮기고 경로 시작 노드를 이전 침실에 남겨 둔 문제였다. 검사 준비의 실제 위치와 경로 노드를 일치시켰으며, 런타임 이동 판정의 허용 범위를 넓히지 않았다.

## 계속 남는 범위

이 작업으로 IG02나 36개 사건 조합을 완료 처리하지 않는다. 사적 초대장 원물의 수정·버전별 전달, 다른 참가자의 독립 원문·장소 목격, 미수신으로 인한 엇갈린 참석과 오해, 변경 전달·재협상·정정의 전체 생활 사건 흐름이 남는다. 현재 재협의 답변은 다른 조건을 다시 제안해 달라는 요청이며, NPC가 구체적인 대체 약속을 건네는 협상과 같은 약속의 수정 UI는 후속 작업이다. UI·대사·그래픽의 추가 개선도 전체 목표 안에 유지한다.

## 최종 검증

- PlayMode `BL22-v21-final2.xml`: 52/52 통과, 129.03초. 기존 관련 45개와 새 약속 검사 7개다. 제안·답변·중단·저장 복원·빠른 진행·미수신 수락 거절·장소 목록 UI·실제 NPC 이동·원격 만남 비생성을 확인했다.
- EditMode `BL22-v21-domain.xml`: 19/19 통과. 기존 약속 버전별 수신·수락, 인물별 제안 판단, 개인 지식과 사건 규칙의 관련 검사다. 전용 초대장 원물 또는 IG02 전체 조합의 실행 검사로 세지 않는다.

선택 화면의 실제 렌더에서 키보드 초점과 선택 항목의 색이 함께 보이는 점을 확인했다. 고른 장소에는 ‘선택한 장소’ 문구를 추가했다. 행 버튼을 재생성하지 않고 문구를 갱신해 기존 키보드 초점과 스크롤 대상을 유지한다. 이 보완 뒤 `BL22-v21-choice-final.xml`에서 약속/대화 선택 관련 8/8개를 재검사했다(31.66초). 앞의 52개와 겹치는 검사이며 합계에 중복 추가하지 않는다.

- Windows `BL22_v21_build2.log`: 빌드 성공, 오류 0, 기존 경고 4, 24.27초.
- 네이티브 `BL22-v21-smoke2`, RunId `20260925T202730728Z`: PASS_SMOKE_ONLY. 1280×720·1920×1080에서 합계 64개 화면, 런타임 오류 0. 새 장소 선택·제안 중·답변 중·확정 화면을 추가하고 기존 인물/대여·반납/설정 복원을 함께 확인했다.
