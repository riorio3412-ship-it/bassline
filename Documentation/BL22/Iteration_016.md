# 0.16 — 실제 발언과 오해 정정

2026-09-26. 직전 0.15는 공용 반납·수거·정리함과 장부, 대화 선택지 개선을 실행 빌드로 전달한 진전이었다. 이번 작업은 IG01의 잘못된 주장과 정정, 인물의 거절과 관계 반응을 실제 대화에 연결한다. 전체 기획 범위는 유지한다.

## 플레이 흐름

공용 반납대에 펜을 놓은 뒤 태겸이나 민서와 이야기하면 ‘펜이 사라진 일’을 고를 수 있다. 일반 대화의 기본 화면에 관련 상황에서만 나온다. ‘민서가 훔쳤다고 말하기’는 실제로 그 말을 하겠다는 명시적인 선택이다. 플레이어의 말도 월드 시간에 따라 발화하고, 상대가 듣고 답한다. 버튼을 누르자마자 모든 사람이 사실을 알게 되거나 관계가 바뀌지 않는다.

끝까지 들은 인물에게만 완성된 주장을 남긴다. 늦게 다가오거나 중간에 듣지 못한 사람은 들은 부분만 기록한다. 멀리 있는 사람의 기억에는 쓰지 않는다. 플레이어가 중간에 대화를 닫으면 실제로 발화한 부분을 보존한다. 플레이어와 상대 모두 대화에 참여하는 동안 서 있고, 대화 종료 후 원래 활동과 이동 계획을 이어간다.

민서가 직접 단정적인 주장을 들었다면 불쾌함을 표현하고 펜에 관한 추가 질문을 거절한다. 공용 정리함과 장부는 계속 공개되어 있다. 원물의 고유 흔적과 이번 대여 이후의 공용 정리 기록을 실제로 확인해야 ‘확인한 내용을 설명하기’가 열린다. 과거 대여 때의 기록을 이번 수거의 근거로 재사용하지 않는다. 근거 확인 전에도 ‘내가 단정했어. 미안해.’라고 잘못된 단정을 거둘 수 있다.

정정도 직접 들은 사람에게만 적용한다. 한 사람에게 사과했다고 멀리 있는 다른 청자의 기억을 고치지 않는다. 처음 주장은 지우지 않고 정정 발언을 별도로 보존한다. 민서가 들은 단정과 이후 사과는 별개의 관계 경험으로 남으며, 사과 한 번으로 이전 손상이 모두 없어지거나 반복 사과로 신뢰를 얻지 않는다. 이 경미한 오해에서 살인 사건·재판·처형을 시작하지 않는다.

## 검증 중의 수정

초기 23개 PlayMode 검사가 통과했다. 이어 이동 중인 상대가 플레이어의 발언을 듣는 동안 기존 경로로 걸어가 버릴 수 있음을 코드에서 확인해 참가자 대기와 원래 활동 복원을 추가했다. 새 이동 복원 검사의 첫 실패는 테스트에서 태겸을 배치한 자리가 화분과 겹쳤기 때문이었다. 고정 충돌 판정을 완화하지 않고 검사 배치를 기존의 빈 자리로 수정했다. 이후 결과와 Windows 화면 검증은 아래에 기록한다.

## 기능 검증 결과

- `BL22-v16-discussion-final.xml`: 대여·물리 전달·공용 정리와 새 오해 정정 검사 24/24 통과. 기존 18개와 새 대화 검사 6개다. 실제 청취자 구분, 늦게 들은 말의 부분 기록, 중간 발화 저장·중단, 각 청자별 정정, 반복 사과 중복 차단, 공개 경로 확인 후 설명, 대화 참가자 이동 복원을 다룬다.
- 설명의 원본 근거 ID는 발화자의 감사용 참조다. 말하지 않은 장부 전문이나 원물의 독립 관측을 듣는 사람에게 자동 복사하지 않는다. 청자는 실제 설명 발언을 전언으로 받는다.
- 문장을 화면에서 읽기 쉬운 짧은 줄로 다듬은 뒤 `BL22-v16-dialogue-regression.xml` 8/8 통과. 기존 발화·대화 선택지 이동·이전 저장 불러오기를 확인했다. 위 24개와 다른 검사다.

테스트의 최초 인물 배치는 명시적인 검사 조건이다. 자연 플레이의 모든 상황과 모든 동선을 완주했다는 뜻은 아니다.

## 실제 실행 화면

첫 Windows 검사 `BL22-v16-smoke1`(20260925T175747647Z)은 주요 화면과 새 오해 대화 52개 캡처, 실행 오류 0, 대여·반환 및 오해 대화 확인으로 PASS_SMOKE_ONLY였다. 조작 설정도 복원했다. 새 검사에서는 플레이어만 반납대와 민서 가까이에 검사 목적으로 배치하고 실제 배치·대화 버튼·발화·거절·정정·펜 회수를 실행했다. NPC를 재배치하거나 지식을 주입하지 않았다. 민서가 원물을 실제로 수거·운반하는 경우는 앞의 별도 PlayMode 검증 범위다.

새 선택지·플레이어 발화·민서의 거절과 정정 후 대화를 실제 PNG로 열어 확인했다. 질문을 첫 선택으로, 비난을 그 뒤로 배치했다. 화면에서 발화 안내의 마지막 한 글자가 별도 줄로 꺾이고 일부 대사가 길게 이어지는 것을 확인해 안내와 대사를 짧은 줄로 다듬었다. 최종 실행 결과는 이후 기록한다.

‘민서와 나눈 대화’가 상대의 발언만 필터링하던 기존 동작도 보완했다. 새로 추가한 플레이어 발언의 대화 상대를 함께 저장해, 자신의 단정·사과와 상대의 답을 한 목록에서 읽을 수 있다. 과거 주장을 삭제하지 않는다. 화면 검사 도구에서 UI 어셈블리를 직접 참조해 컴파일 오류가 한 번 발생했으며, 기존 검사 도구와 동일한 리플렉션 접근으로 수정했다. 최종 기능 검사 `BL22-v16-final2.xml`은 32/32 통과했다. 이는 앞서 다룬 24개+8개를 최신 코드에서 함께 다시 실행한 결과이며 64개로 합산하지 않는다.

## 남은 범위

IG01 전체 완료는 아니다. 사적 메모 오독·개인 가방 앞의 변형, 명확한 지시/무지시/메모 오독의 세 조건 완주, 학습 1회와 프로필 보상 원장 연결은 남아 있다. 잘못된 주장이 다른 NPC의 자발적 재전언으로 퍼지는 확장 역시 아직 없다. 현재는 실제 현장의 직접 청취자와 명시적으로 선택한 대화를 다룬다.

최종 인물·환경·동작·음향·전체 대사 및 나머지 사건 문법·반복 플레이·릴리스 기준도 계속 제작해야 한다. 0.16을 전체 게임이나 최종 아트의 완성으로 세지 않는다.

## 최종 화면 확인 및 빌드

`BL22-v16-smoke3`은 대화 기록 화면의 실제 버튼 이름이 ‘대화로 돌아가기’인데 검사 도구가 ‘뒤로’를 찾으면서 중단됐다. 런타임 오류는 없었다. 검사 버튼 이름을 바로잡았다. 동시에 720p의 세 줄 대사 마지막 줄이 조금 잘리는 것을 실제 캡처에서 발견해, 글자 크기를 줄이지 않고 대화 패널과 본문 읽기 영역을 넓혔다.

최종 Windows 빌드(`BL22_v16_build5.log`)는 오류 0, 경고 4, 24.10초로 성공했다. 최종 실행 검증 `BL22-v16-smoke4`(20260925T180951615Z)는 PASS_SMOKE_ONLY, 1280×720·1920×1080 합계 54개 캡처, 런타임 오류 0이다. 실제 대여·반환, 플레이어 발화·거절·정정, 대화 기록과 조작 설정 복원을 확인했다. 720p 선택지·정정 답변·대화 기록 PNG를 직접 열어 세 줄 대사가 모두 표시되고, 플레이어와 상대 발언이 함께 읽히는 것을 확인했다. 자동 실행 검증은 전체 게임 완주나 최종 아트 승인으로 간주하지 않는다. 민서의 임시 3D 모델은 여전히 교체 대상이다.

배포 폴더로 복사한 실행 파일과 데이터 347개를 원본 빌드와 SHA256 비교했고 모두 일치했다. 기존 버전은 보존했다. 검증 기록은 Verification/BL22-v16-delivery.json에 남겼다.
