# BASSLINE

Unity 6 / C#로 처음부터 만든 **시스템 프로토타입 0.1**입니다. 18명의 세계 상태, 행동, 사건, 증거, 재판과 반복을 하나의 실행 흐름으로 연결합니다. 완성 게임이나 원문의 모든 콘텐츠를 구현한 버전은 아닙니다.

## 실행

1. Unity Hub에서 이 폴더를 프로젝트로 추가하고 **Unity 6000.6.0f1**로 엽니다.
2. 상단 **BASSLINE → Create entry scene**을 누른 뒤 **Play**를 누릅니다. 빈 씬에서도 Play 시 런타임이 자동 시작합니다.
3. 타이틀에서 **새로운 입장**을 선택합니다. 기본 시드는 `1709`이며 시드를 바꾸면 다른 행동 순서가 생성됩니다.
4. 규칙을 읽고 일상을 시작합니다. 다른 참가자와 대화하거나 시간을 진행하세요.

Windows 실행 파일은 **BASSLINE → Build Windows** 또는 `Build-Windows.ps1`로 만듭니다. 결과는 `Build/BASSLINE.exe`입니다. Unity 라이선스가 활성화되어 있어야 합니다. 자동화 환경에서 라이선스 IPC 연결이 거부되어 이 납품에는 검증되지 않은 실행 파일을 포함하지 않습니다.

## 조작

| 조작 | 동작 |
| --- | --- |
| WASD / 마우스 | 1인칭 이동 / 시점 |
| Shift | 빠르게 걷기 |
| E | 바라보는 문, NPC, 자료와 상호작용 |
| Tab | 조사수첩 / 참가자 / 공동 기록 / 지도 / 규칙 / 회차 기록 |
| Space | 세계 시간 1분 진행 |
| F5 | 저장 |
| T | 조사 종료 후 재판 시작 |
| Esc | 일시정지 / 대화·수첩 닫기 |

실시간 8초가 세계 시간 1분입니다. 문으로 방을 이동해도 한 턴이 흐릅니다. 대화창·수첩·일시정지 중에는 자동 시간이 멈춥니다. 사건 발생은 플레이어가 누르는 사건 버튼이 아니라 NPC의 압박·갈등·현재 위치·소지품 조건에 따라 결정됩니다. 아무 사건 없이 협상과 화해가 일어나는 턴도 있습니다.

사건 뒤에는 현장과 **기록 보관실·도서실·작업실**의 책상 위 자료를 E로 조사하고, NPC에게 증언을 요청합니다. 자료를 모으지 않고도 재판을 시작할 수 있으므로 준비 여부는 플레이어가 결정합니다. 저택은 실제 1인칭 공간이며, 현재 방에서 문을 조사하면 WorldState의 연결을 따라 다음 방으로 전환됩니다. 연속된 거대 심리스 맵은 아닙니다.

재판 상단의 살아 있는 참가자를 눌러 개입 대상을 지정합니다. **질문·동의·발언 요청·반박·논점 변경·관찰**을 사용할 수 있습니다. 단서 연결에서 A/B 자료와 관계를 선택해 주장합니다. 질문과 발언 요청은 상대가 가진 정보를 공개하도록 유도합니다. 자동 토론은 일시정지할 수 있습니다. 세 차례 발언 이후 투표가 열립니다.

## 구현한 것

- 원문 18인의 이름·성별·나이·6개 능력치·3개 성향·외형·성격·계약·관계를 데이터화했습니다. 게임 내 인물 소개는 공개 정보만 보여 줍니다.
- 28개 방(공용 10개, 객실 18개), 연결 그래프, 위치, 물품 보관자와 이동 이력, 방향별 관계, 압박과 공포, 공통 이벤트 로그를 관리합니다.
- 방 단위 턴 시뮬레이션으로 NPC 이동, 갈등, 도움 요청, 화해와 물건 인계를 처리합니다.
- 실제 갈등 이력과 소지품, 동시 위치 조건이 맞는 사건만 생성합니다. 1~2명 피해자, B2의 최대 3명, 소수 생존자 상한을 처리합니다. 피해자별 갈등 이유를 남깁니다.
- 독립적인 두 조사 경로, 실제 사건 시각, 증거 출처, 접근성, 다른 용의자 배제와 최소 생존자 수를 검증합니다. 검증 실패 시 상태를 되돌립니다.
- NPC 지식, 근거에 따른 가설, 공개 발언, 사회적 투표를 분리했습니다. 알려지지 않은 단서나 내부 범인 ID를 추리에 사용하지 않습니다.
- 재판에서 공개된 원본은 지식을 갱신합니다. 관계 때문에 가설과 다른 표를 던질 때는 그 이유를 내부 기록에 남깁니다. 기본 투표는 익명이며 A9만 익명 해명을 공개합니다.
- 동률이면 해당 후보로 1회 재투표하고, 재동률이면 공개 추첨합니다. 잘못된 판결에서도 생존자가 3명 미만이 되지 않게 합니다.
- 시드와 난수 진행 상태, 장·규칙·지식·사건·투표·기록을 JSON으로 저장합니다. 3명에서 새 회차가 시작되며 NPC 기억은 초기화하고 플레이어 기록은 보존합니다.

저장은 프로젝트 또는 실행 파일 옆 `Saves/session.json`에 둡니다. 마지막 파일을 `.bak`으로 보관합니다. 다른 사람에게 프로젝트를 전달할 때는 개인 플레이 기록을 포함할지 확인하세요.

## 규칙 범위

기존 **40개 규칙 원문**과 **미확정 신규 12개**를 모두 카탈로그에 넣었습니다. 실제 추첨에는 다음 12개만 들어갑니다.

| ID | 실제 효과 |
| --- | --- |
| A1 | 최다 지목자 퇴장, 오답 시 범인 탈출, 추가 무고자 중복 퇴장 없음 |
| A7 | 미리 지정된 2명의 투표권 제외, 발언권 유지 |
| A8 | 조사 전 의심표 봉인, 플레이어 직접 제출, 최종 투표 전 공개 |
| A9 | 최종 득표와 익명 투표 이유 공개 |
| B2 | 피해자 상한 3명, 최소 8인 조건 |
| B5 | 객실과 개인 가방 재배정, 이전 기록 보존 |
| B8 | 통로 연결과 NPC 이동 경로 변경, 지도 반영 |
| C1 | 생성된 공식 기록 한 개 전원 공개 |
| C6 | 최초 진술 원문 봉인, 진위 미확인 표시 |
| D7 | 신뢰 명단 공개와 제외된 사람의 관계 변화 |
| D9 | 계약자 1인 압박 증가, 판결 후 보상 만료 |
| D10 | 첫 사건 가능 시점을 늦추는 추가 자유행동 시간 |

첫 두 장은 한 개, 세 번째 장부터 25% 확률로 서로 다른 유형의 보조 규칙을 추가합니다. 동시에 최대 두 개, 중대 최대 한 개, 직전 규칙 제외, 인원·장 조건을 적용합니다. 기존 28개 미구현 규칙과 신규 제안 12개는 **추첨 제외**입니다. 신규 B11은 기존 B8과 병합 후보이며, A11/A8과 B12/B4도 확정하지 않았습니다.

## 현재 한계

- 사건 템플릿은 **닫힌 약속 / 맡겨진 인장** 두 개입니다. 둘 모두 폐쇄 현장과 인장 인계 추론을 공유하므로, 이름·인물·동기·장소가 달라져도 추리 구조의 폭은 제한적입니다. 시각 인증 시설과 보관 인장은 첫 검증용으로 추가한 임시 장치입니다.
- 캐릭터 2D 초상·표정과 3D 인물·저택은 절차적으로 만든 임시 표현입니다. 정식 스탠딩 144종, 성우, 음악, 애니메이션, 캐릭터별 90개 전용 사건은 제작하지 않았습니다. 참고작의 캐릭터·음원·그림은 사용하지 않았습니다.
- AI는 규칙 기반입니다. 자유 문장 입력을 해석하는 LLM이나 자연어 대화 생성은 연결하지 않았습니다. 플레이어는 대상과 의도·근거를 지정해 발언합니다.
- NPC 이동은 방 단위입니다. 방 안의 정교한 경로 탐색이나 군중 애니메이션은 없습니다. UI는 확장 가능한 초기 IMGUI 구현입니다.
- 원문에 완성된 최종 계약 위반 시나리오가 없으므로, 4인에서는 **자발적 계약 포기 확인**이라는 임시 절차를 표시합니다. 정식 최종 심리·세계관 결말을 대체하는 확정 설정이 아닙니다.
- 플레이어도 피해자나 오답 퇴장 대상이 될 수 있습니다. 이 경우 새 회차 시작을 선택합니다. 자동 완주나 특정 인물 생존은 보장하지 않습니다.
- 개발용 이벤트 로그와 저장 파일에는 봉인된 진실이 들어갑니다. 게임 UI와 NPC 추리에는 노출하지 않지만, 저장 파일 변조 방지나 보안 기능은 없습니다.

## 검증

`Run-CoreTests.ps1`은 .NET 10 SDK로 외부 테스트 패키지 없이 실행합니다. 120개의 사건 생성 시드, 250개 시드 × 8장의 규칙 조합, 정답·오답과 5~18인의 정산 경계, 전체 회차 진행, 지식 누출 방지, 증거 두 경로, 저장 난수 복원을 검사합니다.

현재 **54,627개 assertion 통과**, 17명의 서로 다른 범인과 두 템플릿을 확인했습니다. Unity 6000.6.0f1의 실제 DLL을 참조한 전체 C# 컴파일도 통과했습니다. Unity Editor 실행은 라이선스 IPC 연결에서 막혀 **Play Mode, Windows 빌드, 실제 화면 검증은 미완료**입니다. 소스 컴파일 결과를 실행 검증으로 간주하지 않습니다.

Unity 빌드 후 아래처럼 시각·저장 스모크 테스트를 실행할 수 있습니다. 이 테스트는 타이틀, 탐색, 수첩, 재판, 판결 스크린샷을 지정 폴더에 저장합니다. 일반 플레이와 같은 JSON 저장 경로를 사용하므로 테스트 전 기존 저장을 백업하세요.

```powershell
.\Build\BASSLINE.exe --qa "$PWD\QA" -screen-width 1600 -screen-height 900 -screen-fullscreen 0
```

## 코드 구조

`Assets/Bassline/Core/`에는 Unity에 의존하지 않는 시뮬레이션과 추리·판결 코드가 있습니다. `Presentation/`에는 1인칭 저택과 화면, `Editor/`에는 씬·빌드 생성, `Resources/Content.json`에는 출연진과 규칙을 둡니다. `Docs/Reference-extracted.txt`는 제공된 기획서의 읽기용 추출본이며 개발 실행 지시로 취급하지 않았습니다.

다음 콘텐츠 확장은 다른 구조의 사건 템플릿, 캐릭터별 전용 갈등, 나머지 규칙 효과와 충돌 검증, 정식 최종 계약 심리, 정식 아트 순으로 진행할 수 있습니다.

빌드 스크립트는 [Unity 공식 명령행 빌드 문서](https://docs.unity3d.com/6000.0/Documentation/Manual/build-command-line.html)의 `-executeMethod`와 `BuildPipeline.BuildPlayer` 방식을 사용합니다.
